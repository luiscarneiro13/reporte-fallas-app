CONTEXTO
Documentación completa y actualizada de todo lo que necesita la pantalla
"Reportar falla" de la app móvil. Reemplaza cualquier versión anterior de
este mismo prompt — se corrigieron varios detalles de orden/formato que no
coincidían con la web.

Auth: header Authorization: Bearer {token} (Sanctum, obtenido en
POST /api/v1/login). Envelope de todas las respuestas:
{ "success": bool, "message": string, "data": {...}|null, "errors": {...}? }

═══════════════════════════════════════════════════════════════════════════
PASO 1 — CATÁLOGOS PARA LOS DROPDOWNS
═══════════════════════════════════════════════════════════════════════════

GET /api/v1/fallas/crear-datos
Método: GET, sin body ni query params.
Auth: solo requiere estar logueado (sin permiso extra específico).

Este único endpoint trae TODOS los catálogos que necesita la pantalla.
Úsalo siempre al entrar a la pantalla, antes de mostrar el formulario.

REGLAS DE CADA CATÁLOGO (idénticas a la pantalla web /v1/admin/fallas/create):
- Todos son objetos { "id": "texto" }. SIEMPRE traen "0": "Seleccione" como
  primera entrada — úsala como placeholder/valor inicial del select, NO
  preselecciones el primer elemento real de la lista.
- equipment: ordenado alfabéticamente por modelo del vehículo. Texto:
  "Tipo - Código interno - Placa - Modelo".
- service_area / fault_status / spare_part_status: ordenados alfabéticamente
  por nombre.
- employee_reported: solo empleados internos (no externos), ordenados
  alfabéticamente por apellido. Texto: "Cédula - Apellido Nombre".
- executors_internal / executors_external: mismo formato que
  employee_reported, pero NO se usan en esta pantalla (son para Cerrar
  falla). Ignóralos acá.
- fault_status excluye en la práctica cualquier estado "cerrado" (no hay
  ningún registro con ese nombre en el catálogo real).

REGLA ESPECIAL — usuario con rol "Operador" (revisar `roles` del login):
- fault_status: viene con UN SOLO valor fijo (sin "Seleccione", sin más
  opciones) — mostrar ese campo bloqueado/no editable con ese único valor.
- default_fault_status_id: el id a preseleccionar y fijar en fault_status_id.
- default_employee_reported_id: el id a preseleccionar en employee_reported_id
  (normalmente el propio empleado del usuario). El campo puede quedar
  editable o no según se decida en la UI, pero debe venir precargado.
- report_date: precargar con la fecha de hoy; en la web este campo queda
  disabled para este rol.
- spare_part_status_id deja de ser obligatorio para este rol (ver reglas de
  validación abajo).
Si el usuario NO es Operador, default_fault_status_id y
default_employee_reported_id vienen null — no hay preselección forzada.

═══════════════════════════════════════════════════════════════════════════
PASO 2 — ENVIAR EL FORMULARIO
═══════════════════════════════════════════════════════════════════════════

POST /api/v1/fallas
Permiso requerido: "Fallas Crear" (del array `permissions` del login).

CAMPOS:
┌─────────────────────┬──────────────────────┬──────────┬───────────────────────┐
│ Label                │ Campo (body)          │ Tipo     │ Requerido              │
├─────────────────────┼──────────────────────┼──────────┼───────────────────────┤
│ Reportado por         │ employee_reported_id  │ integer  │ Sí                     │
│ Equipo                │ equipment_id          │ integer  │ Sí                     │
│ Área de servicio      │ service_area_id       │ integer  │ Sí                     │
│ Status de la falla    │ fault_status_id       │ integer  │ Sí                     │
│ Status de repuestos   │ spare_part_status_id  │ integer  │ Sí, salvo rol Operador │
│ Descripción de falla  │ description           │ string   │ Sí                     │
│ Fecha del reporte     │ report_date           │ date     │ No                     │
│ Ejecución planificada │ scheduled_execution   │ date     │ No                     │
└─────────────────────┴──────────────────────┴──────────┴───────────────────────┘

Formato de fecha: "YYYY-MM-DD".
NO enviar "0" (el valor de "Seleccione") en ningún campo obligatorio — el
backend lo rechaza con 422 porque no existe ningún registro con id=0 (mismo
comportamiento que la validación de la web).
NO existen en esta pantalla: executor_id, executor_external_id,
completed_execution, equipment_maintenance_log — esos son exclusivos de
Cerrar falla, no los envíes al crear.

NOTA
═══════════════════════════════════════════════════════════════════════════
GET /api/v1/fallas/crear-datos y el POST comparten la misma fuente de datos
que la pantalla web (mismo Service, mismo código) — cualquier cambio futuro
en el orden/formato de los dropdowns en la web se refleja automáticamente
acá, sin volver a desincronizarse.
